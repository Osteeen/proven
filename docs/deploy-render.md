# Deploying Proven to Render

Proven runs on the **PayPal sandbox only**. The app refuses to start with a live PayPal setting, a missing secret, or a non-https `AUTH_URL`.

What gets created (from `render.yaml`):

| Resource | Plan | Notes |
|---|---|---|
| `proven-db` (Postgres 17) | `free` until about Nov 1, then `0.1c-256mb` ($10.50/month) | **Upgrade before the free database expires (30 days after creation, about Nov 11)** - upgrading keeps the data; an expired one is deleted 14 days later, before judging. No outside connections (`ipAllowList: []`). |
| `proven` (web service) | `free` | Sleeps after 15 minutes idle (about 1 minute to wake). Move to a paid plan for judging (about Nov 25) if credits allow. |

Proven and Cosign share one $50 Render credit. **Check each plan's monthly price in the dashboard before you apply.**

## 1. Create the services

1. Render dashboard > **New** > **Blueprint**, connect GitHub, and pick `Osteeen/proven` (branch `main`).
2. Render reads `render.yaml` and lists `proven-db` and `proven`. Check the plans and prices shown.
3. Fill in the values it asks for:

| Key | Value |
|---|---|
| `AUTH_URL` | `https://proven.onrender.com` - if Render gives the service a different URL, change this after the first deploy |
| `PAYPAL_CLIENT_ID` | from your `.env.local` (paste it yourself) |
| `PAYPAL_CLIENT_SECRET` | from your `.env.local` (paste it yourself) |
| `PAYPAL_PARTNER_MERCHANT_ID` | from your `.env.local` |
| `PAYPAL_PARTNER_ATTRIBUTION_ID` | leave empty |
| `PAYPAL_WEBHOOK_ID` | leave empty for now (step 3) - webhooks answer 503 until it is set |
| `DEMO_CHARITY_TRACKING_ID` | `proven-charity-1791502716393` (sandbox ID) |
| `DEMO_CHARITY_MERCHANT_ID` | `AQL8SMVTSXJ66` (sandbox ID) |

`AUTH_SECRET` is generated by Render. `DATABASE_URL` comes from `proven-db`.

4. Apply. The first deploy runs the database migrations and the demo seed, then builds and starts the app.
5. Open `https://<your-url>/api/health` - it should show `{"ok":true}`.

## 2. Log in with PayPal

PayPal developer dashboard (sandbox) > the **Platform Partner App** > Log in with PayPal > add the return URL:

```
https://<your-url>/api/auth/callback/paypal
```

Keep the existing `http://127.0.0.1:3000/...` entry for local work. The app is shared with Cosign; adding a URL doesn't affect it. A new return URL can take a while to apply.

## 3. Webhooks

Same app > **Webhooks** > Add webhook:

- URL: `https://<your-url>/api/paypal/webhook`
- Events: `PAYMENT.CAPTURE.COMPLETED`, `PAYMENT.CAPTURE.DENIED`, `PAYMENT.CAPTURE.REVERSED`, `PAYMENT.CAPTURE.REFUNDED`, `PAYMENT.AUTHORIZATION.VOIDED`

Copy the **Webhook ID** PayPal shows, set it as `PAYPAL_WEBHOOK_ID` on the `proven` service in Render, and save (Render redeploys).

## 4. Check it works

1. `/api/health` shows `{"ok":true}`.
2. `/signin` > demo charity and demo reviewer both open.
3. Give to a need with a sandbox donor account, then release or close it as the demo charity and reviewer.
4. PayPal developer dashboard > Webhooks > the event list shows deliveries to the Render URL with HTTP 200.

## Later

- Before judging: move the web service to a paid plan if the wake-up delay hurts the demo, and add a keep-awake ping.
- The daily lapsed-hold check will run from a GitHub Actions schedule (Render's free tier has no cron jobs).
